llm-eval-harness

Regression testing for LLM outputs: run a model over a categorized suite, record latency, tokens and cost, compare two runs, and fail CI when something that used to pass now fails.

suite (55 cases) ──► model ──► scorers ──► run.json
                                          │
        llm-eval compare a.json b.json ◄──┘  exit 1 on regression
  • Layered scoring: exact match, JSON Schema, embedding similarity, LLM-as-judge
  • Works with any OpenAI-compatible endpoint (OpenAI, Ollama, vLLM); records temperature, seed, p50/p95 latency, tokens, cost
  • Case-level diffs: two runs with the same pass rate can still hide regressions
  • 55 tests; ran live against Gemini (see results below), plus mocked and fake-server tests

sqlite-mcp-explorer

A sandboxed text-to-SQL stack for AI agents: a read-only SQL server over MCP, a natural-language interface, and a benchmark that scores any generator on syntax validity, schema adherence and execution accuracy.

question ──► generator ──► SQL ──► read-only sandbox ──► rows
                                 │
     benchmark: syntax · schema · execution accuracy (53 questions)
  • Defense in depth: read-only connection, SQLite authorizer allow-list, one statement per call, row cap, query timeout
  • Hallucinated columns fail schema adherence; generated writes are flagged unsafe and never run
  • Benchmark answers are executed SQL, not text; CI gate with --min-accuracy
  • 51 tests including attack queries against each safety layer

Live results (Gemini)

96%llm-eval-harness, 53/55, with a "final answer only" system prompt
75%same suite, plain prompt: 41/55, all 13 arithmetic cases failed on formatting
100%text-to-SQL benchmark, 53/53 execution accuracy

Model: gemini-3.1-flash-lite, free tier, temperature 0, one run each, run on 2026-10-22. Caveats: the 75% is a formatting gap, not ability (the model answers "17 + 25 = 42", which fails exact match). The judged cases are graded by the same model. The 96% run used the suite before two prompts were fixed and could not be repeated because the daily quota ran out. The SQL benchmark is small and easy, so 100% shows the pipeline works end to end rather than ranking models, and one question was reworded after a first run scored 98%. Full detail is in each repository's README.
